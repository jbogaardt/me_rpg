# src/core (engine plumbing)

Detail moved out of the root `CLAUDE.md` (which has the layers, commands, procedure and conventions); words such as "above" or "below" inside these bullets refer to this file or the map in the root. Keep the bullet for a feature up to date in the same change.

- **`src/core/`** — engine plumbing. `Scene.ts`: the `Scene` interface (`root`, `enter`, `update(dt)`, `resize`, `exit`) and `SceneManager` (runs one scene from `app.ticker` with a clamped dt, forwards resizes, and always calls `input.endFrame()` after each update). `camera.ts`: integer zoom chosen from the window size (`pickZoom`: the whole number nearest a 640x440 design view, never below 1) and a follow camera with one rule everywhere (`followOffset`, `chase`, `Camera.follow` are pure or nearly: the player is in the middle of the screen, the camera eases after them (`FOLLOW_RATE`) and never leaves the map, `map/bounds.ts` `mapBox`; `Camera.punch` is the iris's momentary extra zoom and `Camera.adopt` hands one zone's view over to the next without a seam). `input.ts`: module-level keyboard + mouse singleton (`isDown`, one-shot `wasPressed`; mouse buttons are `Mouse0/1/2` codes and count only when a real mouse presses the canvas; `isHeld`/`wasHit` are keyboard+mouse only, `isTouched`/`wasTouched` on-screen buttons only; `captureKey` hands the next key to the rebind UI; ignores keys typed into text fields, so pasting a code can't move the hero). `bindings.ts` (Pixi-free, tested): the rebindable controls, two slots per action (`up/down/left/right/attack/inventory`; defaults WASD/arrows, attack = left click or Space, inventory = I; there is no magic key: spells are combos, see Wands, tomes and combos), saved in localStorage; menu/map keys (Esc, Tab, M) are `FIXED_KEYS`, reserved and never hard-coded elsewhere: ask `menuPressed()`, `mapPressed()` and `tabStep()` (left/right *as bound*, so the move keys and the D-pad also flip the tabs of an open menu or shop counter). `tools/ui/touchKeys.test.ts` checks that every `data-key` in `index.html` is a code the game listens for. `controls.ts` joins them to `input` (`actionDown`/`actionPressed`; the on-screen buttons always work too). Game code asks about actions, never raw keys, for movement/attack. The editor is `hud/Keybinds.ts` on the Controls tab, hidden while touch controls are active (no customizing on mobile). **Aim mode** (`aim.ts`, Pixi-free, tested; the choice is saved in localStorage and set on the Controls tab by `hud/AimSetting.ts`): `move` is the original (shots go the way you last walked), `mouse` aims at the pointer: `input.pointer()` is the mouse over the canvas or, on touch, the spot last tapped; `controls.pointerAim(heroOnScreen)` turns it into a unit vector that rides in `Command.aim`. `Simulation.move` sets `Player.aim` (and `mouseAim`) but the hero keeps facing the way they walk; only an attack or a spell turns them toward the mouse (`faceAim`), so range, speed and damage are unchanged. A guest sends it as `InputMsg.am` (1..`AIM_STEPS` directions round the circle; absent = walk aim) and the host decodes it in `HostLink.command`. `touch.ts`: on-screen controls (below). `textures.ts`: `makeFrame` and `sheetGrid`, a per-sheet cache of frame textures. `direction.ts` (facings: `Direction`, `DIRS`/`dirIndex` for the wire, `DIR_VEC`, `directionToward`) and `interp.ts` (`glide`/`approach`, the snapshot smoothing) are the Pixi-free bits the sprites, entities and `net/` all share. `direction.ts` (facings: `Direction`, `DIRS`/`dirIndex` for the wire, `DIR_VEC`, `directionToward`) and `interp.ts` (`glide`/`approach`, the snapshot smoothing) are the Pixi-free bits the sprites, entities and `net/` all share.
- **Touch controls**: `src/core/touch.ts` wires the on-screen D-pad (shown when the primary pointer is a finger or after a touch, hidden again on any physical key press) into `input` as virtual arrow-key presses (`input.setVirtual`), and makes every `[data-key]` element (A = KeyJ, B = KeyK, the ☰ and menu ✕ = Escape) press that key while held, so game code only ever reads key codes. To add a button, add a `data-key` element.
