# src/sprites (paper-doll characters)

Keep it up to date in the same change ("above"/"below" in the text mean this file or the root map).

- **Characters (paper-doll)** — `src/sprites/doll.ts` (Pixi-free) defines the doll sheet and outfits: every layer is packed by `tools/sprites` onto one 832x1600 layout (64px frames for walk/idle/cast/hurt/shoot, 128px frames for the weapon swing; rows up/left/down/right) so layers stack frame-for-frame. An `Outfit` is a part id per slot (`body, head, eyes, hair, beard, torso, legs, feet, hands, cape, headwear, weapon, shield`); `outfitLayers` sorts all layers by `z` (LPC's zPos: lower is behind, so a cape or sword can sit both behind and in front of the body). `src/sprites/Wardrobe.ts` loads parts as plain `<img>` elements (not Pixi textures: they are only drawn onto a canvas, and the browser may drop an unused image's decoded pixels, where an `ImageBitmap` would pin 5 MB per layer) and composes an outfit into one `Texture` on a canvas; mobs of a kind and equal NPC looks share a sheet. Sheets are reference-counted (`sprites/sheetCache.ts`, `RefCache`): every `wardrobe.sheet()` takes a reference that the `Character` holding it gives back on `setSheet` or `destroy` (`releaseSheet`), and a sheet nobody uses is kept as one of `SPARE_SHEETS` (4) spares, then destroyed, so gear changes in a long co-op game don't pile up 10 MB sheets. Only hand a sheet to a `Character` (or release it yourself). **Hero gear** (`systems/items.ts`) has ten slots (`GEAR_SLOTS` in `combat.ts`: `weapon`, `offhand`, `head`, `chest`, `legs`, `feet`, `cape`, `tool`, `bag`, `charm`; only the weapon is always filled; a charm is a talisman with no doll art). Items can also carry buffs: `speed` (% faster, `speedFactor`), `magic`, `regen`/`mpRegen` (per second), `xpBonus`/`goldBonus` (%), summed over everything worn in `combat.ts` and applied in `Simulation` (host/solo only; a guest just sees the result); `rare: true` marks quest rewards (gold slot colour, never in a shop). Add a buff by adding the field to `Item`, a helper in `combat.ts`, `buffTexts` in `hud/itemText.ts` and the rule where it applies and each item carries a `look` (doll slots it sets; the off-hand sets `shield`, so a shield or a mirrored dagger `shield.dagger_left` goes there). `attack`/`defense` of everything worn add up (`gearAttack`/`gearDefense`). `systems/looks.ts` lays every piece over `HERO_BASE` (`heroOutfit`), and `OverworldScene.equip(item)` recomposes the sprite. **Bows** are weapons with a `ranged` field (`speed`, `range`, `cooldown`): the action key plays the `shoot` pose, and the arrow leaves at the release frame (`SHOOT_RELEASE_MS`, via `Player.pendingShot`; a hit while drawing spoils it) along the hero's aim (`arrowEffect`); guests see `draw` and `arrow` events. LPC bows are only drawn in the shoot/hurt poses, so the bow appears while the hero draws it. **Co-op players** each have their own base clothes, ring colour and name (`PLAYER_BASES`, `PLAYER_COLORS`, `playerName`, `playerOutfit(slot, hero)` in `systems/looks.ts`; slot 0 is the solo hero, `heroOutfit`, and online the Dungeon Master, `DM_LOOK`); a guest's one-shot poses (slash/cast/hurt/shoot) are played from the world events, so `Player`'s `body` needs no extra net state. **NPC looks** are `NPC_LOOKS` and **mob looks** `MobKind.look`, both the `sprite` of an entity in `entities.json`. `assets.ts` preloads every part any hero outfit (`allPlayerOutfits`: each item on each base look), NPC or mob kind uses (about 1 MB at boot: every tool writes PNGs through `encodePng` in `tools/map/image.ts`, which stores art of 256 colours or fewer as an indexed PNG, 8x smaller than RGBA); `systems/*` and a test (`tools/sprites/parts.test.ts`) fail on an unknown part, a part in the wrong slot, or a missing body/head.
  - **Custom whole-body parts** (`CUSTOM_PARTS` in `sprites/parts.ts`, `WHOLE_BODIES`): a ready-made 832x1600 doll sheet from `art/` that is not LPC art, e.g. `body.mummy` from `jbogaardt/game-graphics` `dist/mummy_doll.png` (its cast row is a bow draw, so the Mummy uses the sceptre `slash` row for its ray too). `npm run sprites -- build body.mummy` copies it into `public/sprites/lpc/` and the manifest and credits without needing the LPC clone; the part brings its own head, so outfits on it need no `head`.
  - **Part catalog** `sprites/parts.ts` is the source of truth for which LPC art ships (id = `<slot>.<name>` → generator item, body type, colour). `npm run sprites -- build` (with `LPC_DIR` = a clone of the generator) recolours with the generator's palettes, packs each layer to `public/sprites/lpc/<id>.<n>.png` and writes `parts.json` (id → layers with z) and `credits.csv` (per-file authors/licences). Never hand-edit those; commit them with the catalog. See the `add-sprite-part` skill.
  - **Limits**: only weapons whose swing is 128px frames fit (arming sword family, dagger); LPC "oversize" swings (longsword, mace, axe, ...) are 192px and not packed yet. Items missing idle art use the first walk frame; weapons and shields vanish during the cast pose (no art). Body-shaped garments (tunic, pants, boots, armor) differ per body type, so a female NPC needs `f_` parts; hair, hats and weapons are shared. Items with several recolour groups other than skin+eyes are not supported by the packer.
