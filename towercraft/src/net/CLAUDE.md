# towercraft/src/net: online duels and co-op

The title screen's **Solo / Host / Join** picks how to play. Solo is as before (the seeded AI). **Host** picks the format (a duel, or co-op 2 v 1 / 2 v 2: the friend is then the partner, not the rival), the map and a race, gets a two-word game code from Me RPG's relay (`relay/`, the same Worker and `src/net` room codes, `RelayClient`, `PeerLink`: `net/duel.ts` is the one-seat version of `session.ts`) and waits; **Join** types the code and picks a race (the host's map and format are used). Only the connection setup goes through the relay; then the two pages talk directly (public STUN only, so strict NATs cannot connect).

- **Lockstep, not state** (`net/lockstep.ts`): both pages run the same deterministic match and swap only commands. Everything the player does (`Command`: build, train, bunker, garrison, order, focus, castle, upgrade, repair, lane) goes through `cmd()` in `main.ts`: applied at once alone, or scheduled `DELAY` (4) ticks ahead and sent online; each tick both pages apply player 0's commands, then player 1's, then `step`. A tick waits (the "Waiting for your rival" line) until the rival's commands for it arrive. The host is seat 0, the joiner seat 1 (`YOU` in `main.ts`; `Person`), on opposite sides in a duel and on one side in co-op, so never write a `1` for the foe: use `foesOf(match, YOU)`. The channel is **ordered and reliable** (`PeerLink`'s third argument; Me RPG's is lossy).
- **Rules must stay exact**: no randomness or engine-dependent maths in `src/sim` (`hypot.ts`, not `Math.hypot`; no `Math.sin`/`random`). Every `SUM_EVERY` ticks each page sends `checksum(match)`; a mismatch ends the match ("Out of sync"). A new field the rules read must go into `checksum`, and a new player action into `Command` (its `parseCommand` check and a wire test). **Computers hold the other seats and run on BOTH pages** (`makeAis`, `aiSeed`; seats past the two people), seeded from the `go` message's `seed` and reading only the match, inside the tick after the commands: nothing about them crosses the wire. Their memory (`AiState`) goes into `snap`.
- **Rejoin** (`Duel.reopen`, `Lockstep.setAway/snapshot/rejoin/resume`, `packMatch`): the host keeps the relay room open and, when the joiner's link ends, puts a fresh offer in the seat, so the same code lets them back in (the host leaving ends the match: the code is the host's). Meanwhile the match runs on by itself: `Lockstep.away` treats the missing player's commands as empty and skips checksums, so their units march and their towers shoot. On a rejoin the host sends one `snap` message (the match as plain data, the seed and the computers' memory, the tick, its settled commands); that message alone starts the joiner's page (it keeps its old race), which resumes the clock from it. A page never starts a match from `go` while it may be a rejoin: `snap` and `go` are separate messages and art may already be cached.
- **Limits**: both pages hold the whole match, so fog of war is drawn, not enforced (developer tools see through it). A person who drops and never returns leaves their seat to the clock (no computer takes it over), so the host can play on to the win. No pause or in-match leave button yet. A protocol change bumps `NET_VERSION` (3 with co-op: `go` carries a race per seat and the seed; `lane`, `route`; 4: `garrison`).
