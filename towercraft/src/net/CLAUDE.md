# towercraft/src/net: online duels

The title screen's **Solo / Host / Join** picks how to play. Solo is as before (the seeded AI). **Host** picks the map and a race, gets a two-word game code from Me RPG's relay (`relay/`, the same Worker and `src/net` room codes, `RelayClient`, `PeerLink`: `net/duel.ts` is the one-seat version of `session.ts`) and waits; **Join** types the code and picks a race (the host's map is used). Only the connection setup goes through the relay; then the two pages talk directly (public STUN only, so strict NATs cannot connect).

- **Lockstep, not state** (`net/lockstep.ts`): both pages run the same deterministic match and swap only commands. Everything the player does (`Command`: build, train, bunker, order, focus, castle, upgrade, repair) goes through `cmd()` in `main.ts`: applied at once alone, or scheduled `DELAY` (4) ticks ahead and sent online; each tick both pages apply player 0's commands, then player 1's, then `step`. A tick waits (the "Waiting for your rival" line) until the rival's commands for it arrive. The host is player 0, the joiner player 1 (`YOU` in `main.ts`, so never write a `1` for the foe: use `enemy(YOU)`). The channel is **ordered and reliable** (`PeerLink`'s third argument; Me RPG's is lossy).
- **Rules must stay exact**: no randomness or engine-dependent maths in `src/sim` (`hypot.ts`, not `Math.hypot`; no `Math.sin`/`random`). Every `SUM_EVERY` ticks each page sends `checksum(match)`; a mismatch ends the match ("Out of sync"). A new field the rules read must go into `checksum`, and a new player action into `Command` (its `parseCommand` check and a wire test). The AI never runs online.
- **Limits**: both pages hold the whole match, so fog of war is drawn, not enforced (a player reading the match in developer tools sees through it). A rival who leaves or drops loses the match to the other. There is no pause, rejoin or in-match leave button yet. A protocol change bumps `NET_VERSION`.
